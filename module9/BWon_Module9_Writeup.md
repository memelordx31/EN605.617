The main source of difficulty for me in completing this assignment was figuring out a way to integrate the new libraries into my project without having to deviate from the proposed architecture too much. Using Thrust to simplify component code came to mind quite quickly, but I wanted to avoid the additional complexity of using neural networks if possible and struggled to come up with a way of using the math libraries for the purposes of threat detection using the cyber1 dataset. I settled on using cuRAND to implement a Monte Carlo bootstrap and rewrite the brute force attack scoring component, auth\_streams, using cuRAND and Thrust.   

Auth\_streams was written with showcasing CUDA streams and events in mind for Module 6, and functioned by hashing each login attempt and each known attack into user and computer keys, scored both datasets at once in two CUDA streams using pinned memory and asynchronous copies, timed this against a single stream, then reported each dataset's mean anomaly score and percentage of events flagged. In the new implementation, Thrust was used to move statistics such as mean and median anomaly scores and flagged event counts to the GPU, and a Monte Carlo bootstrap implemented with cuRAND is used to provide a null distribution to compare anomaly scores with and measure performance rather than only comparing log data and known attack scores. The initial implementation only measured speed and computed averages on the CPU. The new implementation now keeps the statistics on the GPU and additionally tests whether the scoring methodology is able to separate real attacks from normal traffic.   

When running this module, the bootstrap confirmed that the scorer doesn’t yet effectively separate red-team events from normal traffic. I was unable to implement a scoring logic that deviates attacks from the baseline case during the assignment timeline, so more work will need to be done to improve this component to be actually useful at threat detection tasks for the course project.
